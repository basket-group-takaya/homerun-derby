## 1. 座標系・単位・用語

### 1-1. ワールド座標（`PROMPT.md` §1 準拠）【確定】

右手系。単位はすべて **m / s / rad**（角度の表記のみ度）。

| 軸 | 向き |
|---|---|
| `x` | 一塁方向（＝ライト方向）。三塁側は負 |
| `y` | 鉛直上向き |
| `z` | センター方向。捕手側は負 |
| 原点 | 本塁ベースの先端（ホームプレート後端の頂点） |

- 投手板: `(0, 0.254, 18.44)`
- 右打者の立ち位置: `x ≈ -0.75`, `z ≈ 0`
- 打球の方向角 `φ`: `+z` から `+x` へ回した角。`φ<0` = レフト方向（右打者の引っ張り）、`φ>0` = ライト方向（流し）
- 打ち出し角 `θ`: 水平面からの仰角

### 1-2. 用語

| 記号 | 意味 | 単位 |
|---|---|---|
| `e` | ミート誤差。ゾーン面上でのカーソル中心とボール中心の距離 | m |
| `t` | タイミング誤差。`t = 実スイング接触時刻 − 最適接触時刻`。負＝早い（差し込まれ／引っ張り）、正＝遅い（泳ぐ／流し） | s |
| `u` | アンダーカット量。`u = ボール中心y − カーソル中心y`。正＝カーソルがボールの下＝下から擦り上げる | m |
| `v0` | 打球初速 | m/s |
| `θ` | 打ち出し角 | deg |
| `φ` | 打球方向角 | deg |
| `ω` | バックスピン角速度 | rad/s |

## 2. 画面構成とカメラ 【★要判断1】

### 2-1. 素材の実測事実【確定】

3枚のバッティングシートを実際に開いて確認した結果、**全21コマで打者は画面左を向いている**。
背面図でも顔は画面左を向いており、**投手は画面左側**にあることを示している。
つまり原画のカメラは**一塁側（`+x` 側）から打者の胸側を見た位置**にある。

これは `PROMPT.md` §0-2 の「打者を画面の左〜中央下に配置する」と**両立しない**。
打者を画面左に置くと、打者は画面外を向いて振ることになり、外野を描く場所がなくなる。

### 2-2. 選べる2案

| | 案A（推奨）: 反転しない | 案B: 水平反転する |
|---|---|---|
| カメラ | 一塁側（`+x`）から見る | 三塁側（`−x`）から見る |
| 打者の位置 | 画面**右**下 | 画面**左**下（PROMPT記載どおり） |
| 投手・外野 | 画面左奥 | 画面右奥 |
| 打者の利き | 右打ち（原画どおり） | **左打ちに見える** |
| 絵の忠実性 | 原画のまま。陰影・胸元の配色・ロゴすべて無改変 | 鏡像になる。胸元の配色が左右反転 |
| 引っ張り方向 | 画面奥左＝レフト | 画面奥右＝レフト |

**推奨は案A。** 理由は3つ。

1. `PROMPT.md` §0-2 は冒頭で「**素材に従属させる。ここを間違えると素材が死ぬ**」と書いている。打者位置より素材忠実性が上位。
2. 反転すると3人とも左打ちになる。実在の従業員がモデルであり（§0-4）、利き手を勝手に変える必然性がない。
3. 胸のロゴ・配色を鏡像にすることは §0-4 の「ロゴを改変しない」に触れる可能性がある。

案Aを採ると画面レイアウトは PROMPT の記述と左右反転する。**この差分を承認してほしい。**

### 2-3. フェーズ別カメラ（案A採用時）【要確認】

| フェーズ | カメラ位置 | 注視点 | 備考 |
|---|---|---|---|
| 投球〜スイング | `(9.0, 2.4, -6.0)` | `(0, 1.0, 2.0)` | 固定。ボールは画面左奥から手前へ、スケール拡大で奥行き |
| インパクト | 同上 + FOV −8% | 同上 | ヒットストップ2〜3フレーム＋軽いズーム |
| 打球飛行 | ボール追従。`打球位置 + (12, 6, -14)` を平滑追従 | ボール | 打者は画面外に出てよい |
| 着弾 | 追従継続 + 時間 0.35倍 | 着弾点 | 飛距離テロップ |

投影は素直な透視投影（焦点距離 `f`、`screen = f * (p − cam) / depth`）。実数値は M4 で調整。

## 4. 打撃システム（入力と結果の因果）

`PROMPT.md` §5「打球結果をそれらしい乱数で誤魔化さない」に従い、**乱数は球種・コース選択にのみ使い、打球生成には一切使わない**。

### 4-1. ストライクゾーン面とカーソル

- 判定面は `z = 0`（本塁前縁）の垂直平面
- ゾーン: 幅 `0.4318 m`（プレート幅17インチ）、高さ `y ∈ [0.50, 1.05] m`【要確認: §7-3】
- カーソルは面上を移動。マウスまたはWASD。移動速度 `1.6 m/s` 相当【要確認・M2で調整】
- カーソル半径 `r_cursor` はミートランクで決まる（§8-2）
- **実効捕捉半径** `R = r_cursor + r_ball`（`r_ball = 0.0366 m`）

### 4-2. タイミング

- `t_cross` = ボール中心が `z = 0` を通過する時刻（投球積分から算出）
- スイング入力からバットがミート面に到達するまでの遅延 `T_SWING = 0.130 s`【要確認・M2で調整】
- `t = (入力時刻 + T_SWING) − t_cross`
- 60fps 換算: 1フレーム = 16.67 ms

### 4-3. 判定

`e` = カーソル中心とボール中心の面上距離、`|t|` = タイミング誤差。

| 条件 | 判定 |
|---|---|
| `e > R` | **空振り** |
| `|t| > T_MISS` | **空振り** |
| `e ≤ R_JUST` かつ `|t| ≤ T_JUST` | **ジャストミート** |
| 上記以外で `q < Q_FOUL` | **ファウル** |
| 上記以外で `|φ| > 45°` | **ファウル** |
| それ以外 | `t<0` なら**差し込まれ**、`t>0` なら**泳ぐ**、中間は**芯外し／good** |

```
R_JUST = 0.35 × R      // 実効捕捉半径の内側35%が芯
Q_FOUL = 0.30          // 総合品質がこれ未満はファウル
```

`Contact.kind` との対応（実装がぶれないよう明示する）:

| `kind` | 日本語 | 条件 |
|---|---|---|
| `just` | ジャストミート | `e ≤ R_JUST` かつ `|t| ≤ T_JUST` |
| `good` | 芯外し（良） | `q ≥ 0.55` |
| `jammed` | 差し込まれ | `q < 0.55` かつ `t < 0` |
| `reachedOut` | 泳ぐ | `q < 0.55` かつ `t > 0` |
| `poor` | 凡打 | `Q_FOUL ≤ q < 0.55` かつ `t ≈ 0` |
| `foul` | ファウル | `q < Q_FOUL` または `|φ| > 45°` |
| `whiff` | 空振り | `e > R` または `|t| > T_MISS` |

**調整ダイヤル3つ**（`PROMPT.md` 手順4）は次の3つに対応する。

| ダイヤル | 定数 | 初期値 |
|---|---|---|
| ①ミートカーソル半径 | `r_cursor`（ランク表 §8-2） | S=0.115 〜 E=0.052 m |
| ②タイミング判定の許容フレーム | `T_JUST` / `T_MISS` | `T_JUST=0.025 s`(±1.5f) / `T_MISS=0.115 s`(±7f) |
| ③ヒットストップ長さ | `HITSTOP_FRAMES` | ジャスト3 / good 2 / それ以外0 |

すべて 【要確認・M2の実機で私（経営者）の感触に合わせて調整】。

### 4-4. 打球生成式

```
q_e = clamp(1 − e / R, 0, 1)               // ミート品質
q_t = clamp(1 − |t| / T_MISS, 0, 1)        // タイミング品質
q   = q_e^0.7 × q_t^1.3                    // 総合品質（タイミングを重く見る）
```

**初速**（`PROMPT.md` §0-3 の `v0 = f(パワー, e, t)`）
```
v0 = V_MIN + (V_MAX(power) − V_MIN) × q
V_MIN = 22.0 m/s（≒79 km/h。ボテボテのゴロ）
V_MAX(power) はランク表 §8-2
勇樹「情熱の一振り」: ジャストミート時のみ v0 ×= 1.10
```

**打ち出し角**（`θ = f(弾道, ボール高さ, カーソルY)`）
```
θ = θ_base(trajectory) + K_THETA × k_skill × u + K_HEIGHT × (y_ball − 0.75)
θ を [2°, 48°] にクランプ
K_THETA  = 260 deg/m          // アンダーカット1cmで +2.6°
K_HEIGHT = −6.0 deg/m         // 高めの球ほどわずかに低い打球
k_skill  = 1.5（敦司「上を狙う」）／ 1.0（他）
```

**θ と v0 はトレードオフになる。** アンダーカット `u` を取ると打ち出し角は上がるが、
`u` はそのまま `e` に効くので `q` が下がり初速が落ちる。「振り上げれば飛ぶ」にはならない。
これは現実の打撃と同じ構造であり、意図した設計である。

**方向**（`φ = f(t)`）
```
φ = K_PHI × t          K_PHI = +380 deg/s
|φ| > 45° はファウル
```

符号の意味（右打者）:

| スイング | `t` | `φ` | 方向 |
|---|---|---|---|
| 早い（差し込まれる前に振り切る） | `t < 0` | `φ < 0` | `−x` 側 ＝ **レフト＝引っ張り** |
| ぴったり | `t = 0` | `φ = 0` | センター |
| 遅い（泳ぐ） | `t > 0` | `φ > 0` | `+x` 側 ＝ **ライト＝流し** |

`t = ∓0.05 s` で `φ = ∓19°`。`|t| > 0.118 s` で `|φ| > 45°` となりファウル領域に入るが、
その前に `T_MISS = 0.115 s` で空振り判定になるため、ファウルは主に品質 `q` の低さで発生する。

> 符号は文章で説明すると必ず事故るので、**M1 で「早いスイング → レフト方向」を検証する
> 単体テストを先に書き、テストを仕様の正本**とする。

**バックスピン**（`ω = f(カーソルY, θ)`）— **式そのものが一次情報にある**【確定】

Statcast の実測打球から回帰された式を、そのまま採用する。
出典: Nathan 軌道計算器 セルG4/G5
`https://baseball.physics.illinois.edu/TrajectoryCalculator-new-3D-June2026.xlsx`

```
バックスピン[rpm] = clamp(−763 + 120 × θ[deg] + 21 × φ[deg] × sign, 600, 3600)
サイドスピン[rpm] =       −sign × 849 − 94 × φ[deg]
sign = +1（右打者）
```

`θ` は `u`（カーソルY）の関数なので、これで `ω = f(カーソルY, θ)` が成立する。
**係数を自分で発明せず、実測回帰をそのまま使う**ほうが因果として正しい。

参考値: θ=18° → 1397 rpm ／ θ=24° → 2117 rpm ／ θ=29° → 2717 rpm ／ θ=34° → 3317 rpm。

回転軸は打球方向に直交する水平軸（バックスピン）＋鉛直軸（サイドスピン）の合成。
**総回転数は `Cd` に効く**（§6-5）ので、サイドスピンも抗力計算に含める。

### 4-5. 単調性の保証（`PROMPT.md` §3-4）

上式は次を**構造的に**満たす。M1 で自動テストする。

- `V_MAX` は power ランクに対して単調増加 → **パワー↑で飛距離は減らない**
- `q` は `e` に対して単調減少 → **ミート誤差↑で飛距離は増えない**
- `q` は `|t|` に対して単調減少 → **|t|↑で飛距離は増えない**
- `θ`・`ω` は `e`・`t` に依存しない → 上3つが飛距離の単調性に直結する

## 5. 球種テーブル

**【確定】出典: Baseball Savant Pitch Movement リーダーボード 2025（球数加重平均）**
`https://baseballsavant.mlb.com/leaderboard/pitch-movement?year=2025&min=100`

MLB平均を、NPB先発の平均球速 146.1 km/h（2025年規定投球回、n=47）に合わせて比率換算した。
**NPB列は導出値であり実測ではない【要確認】。** NPBは変化量・回転数を公開していない
（DELTA 1.02 は有料）ため、変化量と回転数はMLB値をそのまま使う。

リリース点は右投手想定。**リリース→本塁プレート前縁の実距離は平均 16.05 m**
（release_extension 平均 1.958 m）。本仕様では 16.70 m を採る。

| 球種 | 表記 | 速度 km/h | 横変化 cm | IVB cm | 総落下 cm | 回転 rpm | 到達 s |
|---|---|---|---|---|---|---|---|
| ストレート | `straight` | 146.5 | 19.8 腕側 | **+40.3** | 37.9 | 2324 | 0.433 |
| シュート | `shoot` | 145.4 | **38.6 腕側** | +18.6 | 60.9 | 2184 | 0.436 |
| スライダー | `slider` | 133.8 | 10.6 グラブ側 | +4.8 | 88.5 | 2431 | 0.472 |
| フォーク | `fork` | 134.1 | 28.4 腕側 | +8.4 | 84.9 | **1355** | 0.471 |
| チェンジアップ | `change` | 132.9 | 36.6 腕側 | +11.4 | 83.9 | 1794 | 0.476 |
| カーブ | `curve` | 124.4 | 22.2 グラブ側 | **−25.9** | 135.1 | 2582 | 0.507 |

- 「腕側」= 右投手→右打者の**内角へ食い込む**。「グラブ側」= 右打者の**外角へ逃げる**
- `IVB` は重力を除いた縦変化（＋＝ホップして見える）。「総落下」は重力込みの実落下量
- 到達時間は抗力積分込み（16.70 m）。**ストレート 0.433 s と カーブ 0.507 s の差は 0.074 s ＝ 約4.4フレーム**
  → 球種の見極めがタイミング判定に直結する。等速式で組むと全球が約20 ms速くなるので**必ず抗力を入れる**
- 実装は §6 の積分器に**回転ベクトルを与えて再現**する。上表の変化量は検証用の目標値であり、数値を直接足さない
- コース選択: ストライク8割／ボール2割。シード付きPRNGで決める
- CPU投手の球種選択は難易度でしか変えない（打者能力に応じた嫌がらせはしない）

## 6. 打球物理（`src/core/physics.ts`）

### 6-1. 積分

- 固定 `dt = 1/240 s`（`PROMPT.md` §2）
- **RK4**（前進オイラーだと dt=1/240 でも 130m 級で数%ずれる）
- 終了条件: `y ≤ 0`（着地）／`t > 15 s`（保険）
- 飛距離 = 着地点の水平距離。**フェンスを越えた打球もそのまま `y=0` まで積分を続けて「到達したはずの距離」を出す**（実況の飛距離と同じ考え方）

### 6-2. 運動方程式

```
F = m·g + F_drag + F_magnus
F_drag   = −0.5·ρ·Cd·A·|v|·v
F_magnus = +0.5·ρ·Cl·A·|v|² · (ω̂ × v̂)
S  = r·|ω| / |v|            // スピンパラメータ
Cl = Cl(S)                  // 経験式（§6-3）
```

### 6-3. 定数表

**【確定】** 出典は Alan Nathan（イリノイ大）配布の軌道計算器および論文。
`https://baseball.physics.illinois.edu/TrajectoryCalculator-new-3D-June2026.xlsx`
`https://baseball.physics.illinois.edu/TrajectoryAnalysis.pdf`
`https://baseball.physics.illinois.edu/ajpfeb08.pdf`

| 記号 | 意味 | 値 | 出典 |

## 7. スタジアム寸法

### 7-1. 球場（架空。実在球場を複製しない）【確定】

NPB12球場の実分布（出典: NPB球場DB `https://npb.jp/stadium/json/` ほか各球団公式）:
両翼 **94〜101 m** ／ パワーアレー **110〜118 m** ／ 中堅 **118〜122 m** ／ フェンス高 **2.5〜5.3 m**（代表 3.0〜4.2 m）。

本作の架空球場は、その分布の中央付近に置く。

| 部位 | 値 | 根拠 |
|---|---|---|
| 両翼（`|φ|`=45°） | **98 m** | 実分布 94〜101 の中央 |
| パワーアレー（`|φ|`=22.5°） | **112 m** | 実分布 110〜118 の下寄り |
| センター（`φ`=0°） | **120 m** | 実分布 118〜122 の中央。**スコア式の120mと一致させる** |
| フェンス高 | **3.6 m** | 実分布の代表値 |
| フェアゾーン | `|φ| ≤ 45°` | — |

**センターを 120 m に置く理由。** `PROMPT.md` §0-1 のスコア式は
`100 + max(0, 飛距離 − 120) × K_dist` であり、120 m を境に加点が始まる。
フェンスをちょうど 120 m に置くと「フェンス越え＝最低100点、越えた分だけ加点」という
きれいな対応になる。指示書が 120 という数字を選んだ意図はこれだと解釈した。
**異なる意図であれば指摘してほしい。**

フェンス距離は `|φ|` の関数として単調補間する（0°→120 m、22.5°→112 m、45°→98 m）。

### 7-1-1. 現実との差（記録）

実際のHRは中央値スプレー角 27.6°＝**パワーアレー方向が大半**であり、
ライン際に集中するわけではない（ライン±10°以内は30%のみ）。
本作は `φ = K_PHI × t` なので**タイミングが合うほどセンター方向**になり、
現実と分布が異なる。現実に寄せるなら打者ごとの引っ張りバイアス `φ_bias` が要るが、
`PROMPT.md` §0-3 は `φ = f(t)` と指定しているので**追加しない**。M7 で必要になれば提案する。

### 7-2. ホームラン判定

打球軌跡が、その `φ` におけるフェンス距離を通過する瞬間の `y` が **フェンス高を超えていれば HR**。
超えていなければ「フェンス直撃」＝凡打扱い（1アウト）。

### 8-2-1. なぜ `θ_base` を高めに置くか（設計制約）

`PROMPT.md` §3-6 は「**完璧な入力で HR率8割前後**」を全選手に求めている。
つまり **パワーC の敦司でも、最善手を打てばフェンスを越えなければならない**。

`PROMPT.md` §0-4 は敦司のスキルを「上を狙う ＝ **弾道2の低さを技術で補える**」と定義している。
つまり **弾道2 は、そのままではフェンスに届かない設定であるべき**で、
スキルを使ってはじめて届くのが正しい。前版で `θ_base(2) = 22°` としたのは
その「補うべき低さ」を消してしまう誤りだったので、18° に下げた。

**§6-3 の確定係数＋§4-4 の回転式で RK4 積分した実測値**（`u = 0`）:

| 選手 | パワー → `V_MAX` | 弾道 → `θ_base` | 回転 | **飛距離** | 滞空 | 頂点 | 120mフェンス |
|---|---|---|---|---|---|---|---|
| 敦司 | C → 166 km/h | 2 → **18°** | 1397 rpm | **116.2 m** | 3.98 s | 14.1 m | **届かない** |
| 貴也 | A → 178 km/h | 3 → **24°** | 2117 rpm | **138.6 m** | 5.44 s | 26.3 m | 越える |
| 勇樹 | S → 185 km/h | 4 → **29°** | 2717 rpm | **143.0 m** | 6.32 s | 36.7 m | 越える |

**敦司はスキルを使わないと越えられない。** スキルを使った場合の最適解も実測した:

| `u`（アンダーカット） | 初速 | `θ` | 飛距離 |
|---|---|---|---|
| 0.000 m | 166.0 km/h | 18.0° | 116.2 m |
| **0.013 m（最適）** | 160.7 km/h | 23.1° | **121.3 m ← 越える** |
| 0.030 m | 153.6 km/h | 29.7° | 115.8 m |

スキルで **+5.1 m** 稼いで、ちょうど 120 m を越える。
「弾道の低さを技術で補う」が数値として成立している。

さらに、この構造は3能力が噛み合っている。

- 敦司はカーソルが大きい（`R`=0.152 m）ので、`u`=0.013 のアンダーカットを**余裕をもって狙える**
- 勇樹はカーソルが小さい（`R`=0.089 m）が、弾道4で**すでに最適角付近**なのでアンダーカットが要らない
- 各初速での最適打ち出し角は 166 km/h→26.5°、185 km/h→25.0°（実測）。
  勇樹の 29° はやや上振れだが、越える距離は十分ある

**残る調整点（M7）**: 現在の `q_t = 1 − |t|/T_MISS` は timing に厳しすぎる可能性がある。
±2フレーム（33 ms）で初速が36%落ちる計算になり、`PROMPT.md` §3-6 の
「完璧で8割、±5で1〜2割」に対して減衰が急すぎる。
`q_e`・`q_t` を二次の減衰（`1 − (x)²`）に変える案を M7 の第一候補として持っておく。
**M7 の実測を見てから決める。今は変えない。**

### 8-2-2. 「完璧な入力」の定義（§14-6 に必要）

`PROMPT.md` §3-6 の「入力精度：完璧」を **`e = 0`** と定義すると、`u = 0` に固定され
打ち出し角を選ぶ自由がなくなり、実際の上手いプレイヤーより弱くなる。
そこで本仕様では次のように定義する。

> **完璧 = `t = 0` かつ、カーソルY位置を「飛距離が最大になる `u`」に置く。**
> `±2フレーム` `±5フレーム` は、その最善手に対してタイミングだけをずらす。

この定義を §14-6 の自動プレイAIに実装する。

### 9-2. スコア式

```
1本あたり = ( 100 + max(0, 飛距離m − 120) × K_dist ) × コンボ倍率
K_dist = 2.0                       // 初期値。§14-6 で調整可
コンボ = 1.0 → 2本目 1.1 → 以降 +0.1 → 上限 2.0。アウトでリセット
```

**先に指摘しておく懸念（実装前の予測。M7で実測する）**

§8-2-1 で実測した最善手の飛距離は 敦司 126 m / 貴也 142 m / 勇樹 149 m。
`K_dist = 2.0` だと1本あたりの得点は **112 / 143 / 158 点**、勇樹は敦司の **1.41倍**。

一方で本数はカーソル面積に効き、勇樹の実効捕捉面積は敦司の **34%** しかない。
`1.41 倍 × 0.34 倍 ≒ 0.48` — **単純計算では勇樹が敦司の半分しか稼げない。**
コンボ倍率も連続HRを要求するので、本数の多い敦司に有利に働く。

`PROMPT.md` §0-1 は `K_dist` とコンボ上限を「調整してよい唯一のスコア係数」としている。
`K_dist` を 2.0 → **4〜6 程度**へ引き上げると勇樹の1本あたり得点は 212〜268 点となり、
比率が `2.0〜2.4 倍 × 0.34 ≒ 0.7〜0.8` まで改善する。それでも足りなければ
固有スキル係数（勇樹の `1.10` と `1.5`）を上げる。

**ただし、上の 0.34 倍は「カーソル面積＝ヒット確率」という粗い近似であり、
実際には球種・コースの分布と `q` の非線形性が効く。§14-6 の実測値を出したうえで提案する。
勝手には変えない。**

### 10-2. 透過アルゴリズム（**試作して検証済み**）

素朴な「背景色から一定距離以内を外周からフラッドフィル」は**失敗する**ことを実測で確認した。
白いユニフォームのパンツが削れた（`PROMPT.md` §0-5 が警告していたとおり）。原因は2つ。

1. パンツのハイライトが背景色に近い（貴也: パンツ `(232,232,233)` vs 背景 `(248,248,248)` = **距離16**）
2. パンツの輪郭線が濃紺ではなく薄いグレーの箇所があり、フィルが漏れて内部を食う

採用する手順は次の5段。

| 段 | 処理 | 目的 |
|---|---|---|
| 0 | 背景色 = シート全体の**最頻色**（外周リングの中央値ではない） | 敦司シートは下端が土色で、リング中央値だと背景色を誤る |
| A | 種点 = 背景色から `seed` 以内の平坦領域を半径 `erode` で収縮したもの | パンツ内の孤立した準白画素が種にならない。**パネル枠の内側にも種が置かれる**ので枠で封じられない |
| B | **局所勾配フラッドフィル**: 隣接画素との色差が `step` 以下なら連結とみなす | 内野ラインと土のグラデーションは越え、キャラの硬い輪郭では止まる |
| C | クロージング（半径 `close`）→ 穴埋め | 輪郭の隙間から漏れた分を修復し、パンツを塊として復元 |

| E | 連結成分＝1体。バットが重なって融合した塊のみ、列密度の谷で分割 | **隣のコマの写り込みを構造的に防ぐ**（各スプライトは自分の画素しか持たない） |

### 10-4. 試作の結果と、M0で直す既知の不具合

21枚を試作して市松背景で目視した結果、**パンツは全21枚で無事**。残る不具合は3件。

1. **足元に土の染みが残る**（yuki の stance / swing_0 / swing_1 / swing_3 / back）。靴の輪郭に囲まれて外部から到達できない土のポケット。→ 暖色（`R−B > 30`）かつスプライト下端20%のポケットを追加除去する
2. **隣のコマのバット断片が混入**（yuki swing_0 の右端、takaya swing_2 / swing_3）。谷分割で切ったバットの残骸。→ 各スプライトで面積が本体の3%未満の孤立成分を捨てる
3. **takaya swing_4 のバットが左端で切れている**。谷分割位置がバットを横切った。→ 分割探索窓を広げ、バットを跨がない谷を選ぶ

### 10-5. スプライトのアンカー

各スプライトに接地基準点 `anchor = (ax, ay)` を持たせないとアニメが跳ねる。

- 自動規則: マスク下端5%の行群における x 重心を `ax`、最下端を `ay` とする
- 手動補正: `assets/player/anchors.json` に per-pose のオフセットを持ち、M2 と M4 で目視調整する
