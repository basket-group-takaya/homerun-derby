# 参照調査：ホームランバトル2（Com2uS）

版: **v1.0** ／ 調査日: 令和8年7月29日 ／ 調査者: 開発セッション

---

## この文書の目的と、はっきりさせておく境界

経営者から「ホームランバトル2をイメージしている。徹底的に調べ上げて、彷彿とさせる AAA ランクの
アプリを作れ」という指示を受けたため、一次に近い情報源を当たって調査した。

**ただし `PROMPT.md` §0 および §5 は「実在の商用ゲームの画像・音声・UIデザインを一切複製しない」を
禁止事項として明記している。** よってこの文書の使い方は次の一点に限る。

| 参照してよいもの | 参照してはならないもの |
|---|---|
| **ゲームシステム**（ルール・スコア設計・モード構成・報酬の置き方） | UIのレイアウト・アイコン・配色・書体 |
| **手触りの作り方**（判定の粒度・カメラの役割・演出のタイミング） | スプライト・背景・効果音・BGM |
| **なぜ気持ちいいのかの構造** | キャラクター・球場・ロゴの意匠 |

以下、確度ラベルを付ける。**【確定】**＝実際に読んだ情報源に明記／**【要確認】**＝推定・裏取り未了／
**【未確認】**＝調べていない。映像そのものは確認していないため、視覚まわりは慎重に扱う。

**重要な含意**：批評の分かれ目は**ゲーム性ではなく課金設計**だった。TouchArcade は

> **我々への示唆**：**コアループは丸ごと参考にする価値があり、収益設計は丸ごと不要**。
> 社内向けの本作は課金が存在しないので、批判された部分を最初から持たずに済む。
> これは「HB2の良いところだけ取れる」という意味で、極めて有利な立ち位置である。

## 2. 操作系（ここが本作と最も近い）

### 2-1. 実際の操作

| 要素 | HB2 | 確度 |
|---|---|---|
| 狙い | 端末を上下左右に**傾ける**（ジャイロ／加速度センサ）と、画面中央の**半透明のバット**が動く | 【確定】 |
| スイング | 画面を**タップ**するだけ | 【確定】 |
| 判定 | タイミングとバットの当たり位置の両方が結果を決める | 【確定】 |

前作 HB3D のレビューはこのカーソルを
「バットの当たり判定を表す小さな白い菱形。ボールが来る瞬間にその上へ重ねたい」と説明している。
また「ボールはプレイヤーのすぐ手前の小さな白い箱に向かって投げられる」とも書かれている。

> **本作との対応**：`PROMPT.md` §0-3 の「ミートカーソル（ゾーン面上の円）＋クリックでスイング」は
> **HB2 と同じ設計である**。マウス＝傾き、クリック＝タップ。つまり操作系は既に一致しており、
> 変更の必要はない。**【確定】この点は既存 SPEC を変えなくてよい。**

### 2-2. 「気持ちよさ」の所在

日本語レビューは一貫して「**ジャストミートした時の気持ちよさ**」を挙げる。
Pocket Gamer は野球の魅力の核を次の3つに要約している —
**バットの快音／打球を目で追う首の動き／観客の歓声**。

> **示唆**：気持ちよさは打球計算の精度ではなく、**インパクトの瞬間の情報密度**にある。
> 我々は M1 で物理を作り込んだが、**打った瞬間に何も起きない**のが現状の最大の欠落である。

## 3. 画面構成

| 要素 | HB2 | 確度 |
|---|---|---|
| 画面上部 | **スコア／ホームラン数／アウトカウント** | 【確定】 |
| 画面中央 | 半透明のバット（＝ミートカーソル） | 【確定】 |
| 画面右上 | 対人戦では**相手のプレイ映像がリアルタイムで常時表示**（2元中継） | 【確定】 |
| グラフィック | "splashy cartoon graphics"（派手な漫画調） | 【確定】 |
| カメラ位置 | **打者の背後（捕手側）から投手を見る視点** | **【要確認】** |

**カメラについて正直に書く。** 映像を確認していないため断定しない。ただし、次の3点は
情報源に明記されており、いずれも「打者の背後から投手を見る構図」でなければ成立しない。

1. ミートカーソルが**画面中央**に出る（横視点ならゾーンは画面の片側に寄り、正対しないので潰れる）
2. ストライクゾーンに正対してカーソルを上下左右に動かす操作が成立している
3. 「ピッチャーが球を投げると」＝**投手が画面内に見えている**

したがって**【要確認・確度高】背面視点**と扱う。実映像で裏を取れていないことは明記しておく。

## 4. ゲームモード（6種）

| モード | 内容 | 確度 |
|---|---|---|
| **Duel** | 1対1のリアルタイム対戦。ゲージを先に満タンにした方が勝ち | 【確定】 |
| **Survival** | アイテムを使う対戦（サバイバル） | 【確定】※詳細未確認 |
| **Mission** | 最大4人。「ホームラン5本」等の目標を**2分以内**に達成。誰も達成しなければ**1分30秒時点で最も近い者**が勝ち | 【確定】 |
| **Burning** | 制限時間制で球が途切れず飛んでくる。**BAD 以外の評価**でメーターが上がり、満タンで**制限時間が完全回復**。対戦では先に満タンにした方が勝ち | 【確定】 |
| **Arcade** | 果てしなく続く1人用。**HR以外のヒットも得点になる** | 【確定】 |
| **Training** | 練習。球種を指定して試せる | 【確定】 |

前作 HB3D の **Classic** モードは「**ホームラン以外は全部アウト。10アウトで終了**」だった。

> **決定的な発見**：`PROMPT.md` §0-1 が定めた本作のルール
> ——「1ラウンド10アウト制。ホームラン以外の打球はすべて1アウト」——は
> **HB3D の Classic モードそのものである。** 偶然ではなく、経営者は最初からこれを見ていた。
> **既存ルールは変更不要。HB2 側から足すべきは Arcade / Burning / Duel の3系統。**

## 5. スコア設計（最重要）

### 5-1. HB3D Arcade の確定仕様

- 打球ごとに得点。**得点は飛距離に比例**する
- **ホームランで +100 のボーナス**
- **連続ホームランでボーナスが 100 ずつ増える**（2本目 +200、3本目 +300 …）
- 連続が途切れる（HRでない打席）と**ボーナスは0にリセット**
- **10アウトで終了**

HB3D Classic は対照的に「**ホームラン1本 = 1点**」だけ。同じ物理・同じ操作のまま、
スコア式を差し替えるだけで別ゲームになる設計。

### 5-2. HB2 で追加された得点要素

| 要素 | 内容 | 確度 |
|---|---|---|
| **ボーナス球** | 投手が「スコア2倍」「スコア3倍」の球を投げてくる | 【確定】 |
| **予告ホームラン** | 宣言して当てるとボーナス | 【要確認】 |
| **的当て** | **ファウルポール**や**電光掲示板**に当てるとボーナス | 【確定】 |
| **観客席3ブロック** | 打球はレフト／センター／ライトのいずれかのスタンドへ入る | 【確定】 |

後継作 Homerun Clash では**ゴールドゾーン／スコアボード／球場内の各種オブジェクト**に
当てると報酬という形に発展している。

> **示唆**：この系統の作品は **「飛距離」だけでは飽きる**と判断し、
> **空間に的を置いて「狙う」動機**を足している。本作の `φ`（方向）はいま結果でしかなく、
> **狙う理由がない**。的があれば方向制御が初めて意味を持つ。

### 5-3. 本作の現行スコア式との比較

```
本作（PROMPT.md §0-1）： Σ( 100 + max(0, 飛距離m − 120) × K_dist ) × コンボ倍率
HB3D Arcade         ： Σ( 飛距離比例 + 100 × 連続本数 )
```

**構造は同型。** 本作はコンボを「倍率」で、HB3Dは「加算」で表現している違いだけ。
本作の方が上限（×2.0）がある分、暴走しにくい。**現行式を維持してよい。**【確定：比較の結論】

## 8. 「AAAランクの手触り」の構成要素（一般的な設計知見）

経営者の言う「AAAランク」を、検証可能な要素に分解する。
Jonasson & Purho の GDC 2012 講演 "Juice it or lose it" 以降、業界で定着した要素は次の通り。

| 要素 | 内容 | 本作での適用 |
|---|---|---|
| **ヒットストップ** | 衝突の瞬間、全体を **1〜5フレーム**止める。脳は「この一撃には意味があった」と読む | `PROMPT.md` §0-6 に既に記載あり（2〜3フレーム） |
| **方向性のある画面揺れ** | 力の向きに沿って揺らし、戻す。**常時揺らすと酔う** | インパクト方向へ短く |
| **パーティクル** | 衝突点から**打撃ベクトルに沿って**外へ噴く | 土煙・光条 |
| **フラッシュ** | 一瞬の白飛び | ジャストミート時のみ |
| **スケール変化** | 押した／当たった瞬間の微小な拡縮（スカッシュ&ストレッチ） | カーソル・テロップ |
| **浮遊テキスト** | 数値がその場に湧いて上へ流れる | 飛距離・得点 |
| **音の重ね** | 単発ではなく複数層（芯・胴・余韻） | WebAudio 合成で層を作る |

**重要な原則**：これらは**掛け算**である。1つでは効かない。同時に起きて初めて「重い」と感じる。
逆に**常時発生させると全部無効化される**（常に揺れている画面は揺れていないのと同じ）。

> **現状の欠落**：本作にはこのうち**1つも実装されていない**。M2 のインパクトは
> 「絵が切り替わって球が飛ぶ」だけである。物理は正しいが、**正しさは手触りではない**。

## 9. 本作に取り込む／取り込まない（提案）

### 9-A. 取り込む（システム）

| # | 要素 | 出所 | 理由 |
|---|---|---|---|
| A1 | 打撃評価の**段階表示**（PERFECT / GOOD / BAD 相当） | Burning のメーター条件 | 因果を毎球フィードバックできる。既に `contact.kind` がある |
| A2 | **ボーナス球**（得点2倍・3倍） | HB2 | 単調さの解消。乱数だが**打球結果は歪めない**ので §5 の禁止に触れない |
| A3 | **的当てボーナス**（ファウルポール・電光掲示板） | HB2 / Clash | 方向制御 `φ` に初めて意味を与える |
| A4 | **バーニング（時間制）モード** | HB2 | 10アウト制と別軸。短時間で終わり中毒性が高い |
| A5 | **アーケードモード**（HR以外も加点・10アウト） | HB3D | 敦司が届かない問題（★要判断6）の**回答候補になりうる** |
| A6 | 実績・デイリー目標（localStorage） | HB2 | 依存0で実装可。リプレイ動機 |
| A7 | 打球の**着弾ブロック表示**（レフト／センター／ライト） | HB2 | 空間認識が上がる |

### 9-B. 取り込む（演出）

| # | 要素 | 理由 |
|---|---|---|
| B1 | ヒットストップ＋方向性のある画面揺れ＋フラッシュ＋パーティクル | §8。**現状ゼロ**。効果が最も大きい |
| B2 | 打球追従カメラの本格化（打った瞬間に回り込む） | 「打球を目で追う」＝野球の快感の中核 |
| B3 | 多層の打球音（WebAudio） | 「バットの快音」＝同上 |
| B4 | 観客の歓声（ホワイトノイズ包絡で合成） | 同上。外部音源0で作れる |
| B5 | 好調演出（連続HR時に打者が輝く。**燃やさない**） | HB2の炎上に相当。§0-4 の「揶揄しない」制約に合わせ、炎ではなく光 |

### 9-C. 取り込まない

| 要素 | 理由 |
|---|---|
| 課金・IAP・ガチャ | 批評家が総叩きした部分。社内向けに不要 |
| 育成・装備・レベル | `PROMPT.md` が3名固定・基礎ランク変更禁止 |
| オンライン対戦・2元中継 | ランタイム依存0・サーバ無しの制約。**ローカル2Pで代替**（§0-1 (b) に既にある） |
| 魔界球場・四神獣 | 世界観が本作（実在社員がモデル）と噛み合わない |
| 外見カスタマイズ50種 | 素材が固定21枚 |
| 傾け操作 | ブラウザ・PC前提。マウスが上位互換 |

## 10. ★要判断（経営者の判断が要る）

### ★要判断7：投球フェーズのカメラをどうするか

`PROMPT.md` §0-2 は**サイドビュー**を指定している。一方 HB2 の手触りの核は
**背面視点**（§3、確度：要確認だが高い）にある。両立しない。

| 案 | 内容 | 得るもの | 失うもの |
|---|---|---|---|
| **(a)** サイドビュー維持 | 現行のまま。システムと演出だけ HB2 化 | 21枚のスプライトが全部生きる。テスト済みの投影を維持 | HB2 の手触りの核が再現できない。ゾーンが斜めで狙いにくい |
| **(b)** 全面的に背面視点へ | HB2 と同じ構図 | 手触りが最も近い | **スイング5コマ×3名＝15枚が死ぬ**（背面のスイング絵が無い）。素材制作からやり直し |
| **(c) ハイブリッド（推奨）** | **投球〜インパクト＝背面視点**（`back.png` ＋コード描画のバット軌跡）／**インパクトの瞬間に横視点のスイング5コマへカット**（0.2〜0.3秒）→ **打球追従カメラへ** | 狙いやすさは HB2 と同じ。**21枚すべて使う**。カット割りが演出そのものになる | 実装が3案で最も重い。カット時の視線の連続性を作り込む必要がある |

**推奨は (c)。** 理由は3つ。

1. HB2 も**打った瞬間にカメラが打球へ回り込む**。カット割り自体が本家の作法である
2. 背面視点では**打者はほぼ見えない**（HB2 も同様）。逆に言えば `back.png` 1枚で足りる
3. スイング5コマは**インパクト直後の 0.2 秒**に集中投入するのが最も映える。
   常時流すより、ヒットストップと同期させた方が「重い」

**(c) が崩れる条件**：カットの瞬間に打者の向きと打球方向が矛盾して見える場合。
これは数値では判定できないので、実装後にスクリーンショットで目視判定する（`PROMPT.md` §3-8 と同じ扱い）。

### ★要判断8：モード構成をどこまで作るか

9-A の A4（バーニング）と A5（アーケード）を作ると、`PROMPT.md` §0-1 のモード
（CPU対戦 / 2P / タイムアタック）と合わせて**5モード**になる。
工数は増えるが、A5 は★要判断6（敦司がフェンスに届かない）の回答になりうる。
